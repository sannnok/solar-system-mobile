# ArmLab — прототип Telegram Mini App по биомеханике армрестлинга

Интерактивная 3D-рука прямо в Telegram. На ней видно, какие мышцы работают в
упражнении, куда направлено усилие, под каким углом стоит сустав и как выглядит
типичная ошибка.

Это прототип, чтобы проверить идею. Модель упрощена, а тексты и веса мышц —
черновик, который должен проверить тренер, прежде чем показывать их как совет.

## Что внутри

| | |
|---|---|
| **5 упражнений** | Подъём на лучевую, пронация, капинг, крюк, боковое давление |
| **Мышцы по усилию** | 23 мышцы от лопатки до кисти, включая вращательную манжету и глубокий сгибатель пальцев. Цвет — усилие мышцы в процентах от её собственного максимума: от синего (стабилизатор) до красного (работает на пределе). По волокнам бегут импульсы. Вклад плечелучевой и бицепса меняется с углом предплечья |
| **Сопротивление** | Трос на блоке или соперник. В крюке три варианта: «против крюка» (соперник тянет к себе и давит к своей стороне, ладонь к ладони), «против верха» (забирается на пальцы и тянет вверх-на-себя) и «блок». У каждого свой вектор, точка приложения и состав работающих мышц |
| **Слабое звено** | Момент силы на каждом суставе против максимума этого движения, вживую по фазам повтора, с ползунком силы соперника или веса на тросе. Максимумы по умолчанию типичные; свои вводятся в «Мои максимумы» и хранятся в CloudStorage Telegram (в браузере — в localStorage) |
| **Настоящая механика** | При пронации лучевая кость перекрещивается с локтевой, мышцы предплечья закручиваются по спирали, а укоротившаяся мышца становится толще |
| **Векторы** | Мятная стрелка — усилие спортсмена, серая — трос, оранжевая — тяга соперника. На суставах показаны углы |
| **Фазы повтора** | Старт → подъём → пик → негатив → пауза. Для каждой фазы своя подсказка, есть перемотка и замедление ½× и ¼× |
| **Типичная ошибка** | Красный «призрак» поверх правильного движения с объяснением, чем ошибка грозит. В боковом давлении показана опасная позиция, в которой ломается плечевая кость |
| **Схватка** | Две руки в захвате: твоя техника против техники соперника (крюк, верх, боковое) и сила соперника (как ты, типичный, верховик, крюковой, сильнее на 30%). Кисти сцеплены в замок: точки хвата совпадают, ладони напротив друг друга. Мышцы обоих горят по механике, а не по заданным весам. Итог — кто держит больше, на сколько и что ломается первым у каждого. «▶ Срыв» показывает, как ломается: сдаёт слабое звено, победитель продавливает замок, а если это пальцы — хват раскрывается и кисть выходит |
| **Хват** | Три ползунка: глубина (от пальцев до ладони в ладонь), чья кисть выше (в сантиметрах) и поворот замка (к крюку или к верху), плюс ремни. Под каждым ползунком — кривая перевеса вдоль него: зелёное — держишь больше ты, красное — соперник. Подсказка считает, сколько стоит сантиметр высоты и 10° поворота, и какую глубину выгодно просить у судьи |
| **Тап по мышце** | Карточка: что мышца делает в армрестлинге, как её тренировать, усилие в реальном времени и риски травм там, где они есть |
| **Telegram** | Разворачивается на всю высоту, есть полноэкранный режим (Bot API 8.0). Свайп вниз не закрывает приложение, поэтому модель можно вращать. Вибро на пике повтора, системные кнопки «Назад» и «Добавить в программу», приветствие по имени |

## Запуск

Сборки нет — это обычная страница на ES-модулях, three.js лежит в `../vendor/`.

```bash
npm start            # из корня репозитория → http://localhost:5173/armwrestling/
npm run mobile       # то же в локальной сети, с QR-кодом; добавь /armwrestling/ к адресу
```

`?debug` в адресе открывает внутренности в консоли (`window.armlab`).

## Как открыть в своём боте

Telegram открывает Mini App только по **HTTPS**, поэтому нужен публичный адрес:

- **Render** (основной вариант): **https://armlab.onrender.com/armwrestling/**.
  Это статический сайт `armlab`, его настройки описаны в `render.yaml` в корне
  репозитория. Сборка `npm run build:armlab` копирует в `dist/` только
  `armwrestling/` и `vendor/three`, так что остальной репозиторий не
  публикуется. Каждый пуш в ветку сервиса запускает новый деплой.
- **GitHub Pages.** Workflow репозитория публикует ветку по умолчанию. После
  слияния эта страница будет доступна по адресу
  `https://sannnok.github.io/solar-system-mobile/armwrestling/`.
- **Туннель** для быстрых проверок с компьютера:
  `cloudflared tunnel --url http://localhost:5173` или `ngrok http 5173`,
  затем к выданному адресу добавить `/armwrestling/`.

Дальше в [@BotFather](https://t.me/BotFather):

1. `/newbot` — создать бота (или взять существующего).
2. `/mybots` → бот → **Bot Settings → Menu Button** → вставить URL и подпись
   кнопки. Mini App откроется из кнопки меню в чате с ботом.
3. Чтобы получить прямую ссылку вида `t.me/<бот>/<app>`, используй `/newapp`.

Серверная часть для этого не нужна: прототип ничего не отправляет.

## Как устроено

```
index.html            разметка, подключение Telegram SDK и import map
styles/app.css        вся вёрстка; учитывает safe area Telegram в полноэкранном режиме
src/
  main.js             сцена, состояние, цикл кадра, ввод
  telegram.js         тонкая обёртка над Telegram.WebApp; вне Telegram все вызовы — no-op
  ui.js               DOM: чипы, таймлайн, переключатель сопротивления, карточка мышцы
  weak.js             экран «Слабое звено» и форма своих максимумов
  matchPanel.js       лист схватки: выбор техник и силы, ползунки хвата с кривыми, вердикт, звенья
  data/
    anatomy.js        мышцы: путь от начала до прикрепления, форма, тексты, рычаг от угла
    exercises.js      упражнения: две позы, варианты сопротивления с весами мышц, векторы, фазы, ошибка
    mechanics.js      виртуальная работа: моменты на суставах от силы и от силы с моментом
    strength.js       движения суставов, их типичные максимумы и какие мышцы их делают
    match.js          схватка: техники, хват, профили, замок рук, статика, пальцы, срыв
  render/
    rig.js            кинематика руки: оси суставов, кости, кожа, рукоять
    muscles.js        мышцы-трубки, которые каждый кадр строятся заново
    overlays.js       стрелки усилия и сопротивления, трос, подписи углов
    camera.js         ракурсы и кадрирование под свободную часть экрана
    materials.js      шейдеры: рентген-кожа, кости, тепловая окраска мышц
    stage.js          стол, подушка, рукоятка-штырь
```

**Упражнение — это данные, а не код.** Новое упражнение — это ещё одна запись в
`exercises.js`: начальная и конечная поза в градусах, одно или несколько
сопротивлений (трос к блоку или тяга соперника из точки хвата) с весами мышц,
векторы усилия и тексты. Ритм повтора и нагрузка по фазам общие.

**Проценты на экране — это усилие мышцы от её собственного максимума, а не её
доля в общей нагрузке.** Абсолютные моменты на локте и плече в 5–10 раз больше,
чем на кисти: предплечье — рычаг около 26 см, а хват смещён от осей кисти на
несколько сантиметров. Но мышцы кисти и в разы слабее, поэтому именно они чаще
работают на пределе. Это и показывает «Слабое звено». В крюке на пределе почти
всегда подъём на лучевую: соперник, который тянет к себе, валит кисть к мизинцу.

**Рука — кинематическая цепь с анатомическими осями.** Плечо вращается вокруг
своей длинной оси, поэтому боковое давление — это внутренняя ротация при локте
на подушке, как и в жизни. Пронация идёт вокруг оси от головки лучевой кости к
головке локтевой: локтевая стоит, лучевая обходит её. Мягкие ткани предплечья
следуют за поворотом частично, от 0 у локтя до 100% у запястья.

**Мышца — путь из контрольных точек.** Каждая точка привязана к своей системе
координат: плечо, локтевая, мягкие ткани предплечья, лучевая, кисть или корпус.
Каждый кадр через точки проводится сплайн, вдоль которого строится
эллиптическая трубка. Брюшко у неё толще, сухожилия тоньше, и она прижата к
конечности. При укорочении трубка утолщается, сохраняя объём.

Модель задана в «зеркальных» координатах, а сцена разворачивает её
`scale.x = −1`, чтобы получилась правая рука (подробности в начале `rig.js`).
Мышцы и стрелки строятся в мировых координатах, поэтому их зеркало не касается.

## Схватка: как считается

`src/data/match.js`. Соперник — та же модель руки, **повёрнутая на 180°**
вокруг вертикали, а не отражённая: зеркальная копия правой руки — левая рука.

1. **Замок.** Хват — это не точка, а замок: точки хвата совпадают, и ладони
   смотрят друг на друга. Все десять суставов обеих рук решаются вместе (метод
   Левенберга–Марквардта), каждый держится как можно ближе к своей технике.
   Поэтому разные техники встречаются посередине: крюк и верх не могут оба
   сохранить свою ротацию предплечья в одном замке.
   - **Поворот замка.** Предплечья стоят почти вертикально, и две правые руки
     вращаются вокруг вертикали в одну сторону. Значит, у замка один поворот на
     двоих, и кто его выигрывает, тот поворачивает обоих. Ползунок задаёт
     среднюю ротацию двух предплечий: минус — к крюку (супинация), плюс — к
     верху (пронация). По умолчанию — посередине между техниками.
   - **Глубина и высота** — где кисть соперника лежит на твоей: от пальцев до
     основания ладони. Кто выше, тот давит у кончиков пальцев соперника, а
     соперник держит его своими пальцами.
2. **Усилие.** Техника — это куда спортсмен тянет (к себе, вверх, к своей
   подушке) и что крутит своими суставами (супинация, пронация, капинг,
   подъём). Кручение — момент вдоль реального вращения его кисти, на ньютон тяги.
3. **Захват.** По третьему закону то, что одна кисть даёт другой, другая
   возвращает с обратным знаком. Оспариваемая нагрузка на твою кисть:
   W = (усилие соперника − твоё усилие) / 2. Где тянут друг против друга, она
   полная. Где крутят в одну сторону, она гасится: два крюка вращают захват в
   одну сторону, поэтому за супинацию никто не борется.
4. **Предел.** Виртуальная работа силы и момента даёт момент на каждом
   суставе обоих спортсменов. Каждый держит W, пока первое звено не упрётся в
   свой максимум. Слабейший ломается там, отношение пределов — это перевес.
5. **Пальцы — тоже звено.** Ладонь может только давить. Пальцы держат то, что
   растаскивает ладони, вытягивает кисть соперника мимо кончиков пальцев и
   отрывает хват кручением (момент, делённый на ширину контакта). Сколько от
   силы на кистевом динамометре пальцы реально используют, зависит от того, где
   в них лежит кисть соперника: обхват ладонью — 100%, на костяшках — 50%,
   кончиками — 30%. Ремни снимают эту нагрузку с пальцев.
6. **Срыв.** Проигравший сдаёт своё слабое звено: сустав поворачивается туда,
   куда его давят. Победитель продавливает замок по своему вектору тяги
   локтем и плечом, руки остаются в замке. Если сдали пальцы, хват
   раскрывается, и кисть победителя выходит из захвата.

Кручение кисти восстанавливается по скоростям трёх точек вокруг хвата, а не
поворотом векторов осей. Поэтому знаки верны и в зеркальной модели, и у
повёрнутого соперника.

Что модель говорит сама, без подгонки:

- **При равных максимумах крюк сильнее верха** примерно на 45%. В нейтральном
  замке всё держит подъём на лучевую верховика. Против «верховика» с сильной
  лучевой и пронацией уже верх выигрывает 9%. То есть верх требует сильной
  кисти.
- **Высота решает больше всего:** около 20% перевеса за каждый сантиметр.
- **Поворот замка в глубокую супинацию крюку невыгоден:** тяга верховика на
  себя ложится прямо на капинг, и он первым упирается в максимум. Крюку
  выгоднее держать замок ровно.
- **Срыв хвата при типичных максимумах почти не наступает:** раньше сдаёт
  запястье. У сильных рук он появляется у нижней кисти на мелком хвате. Верх
  против крюка нагружает пальцы крюка: это и есть механика верха. Глубина
  становится важной именно здесь: она возвращает пальцам обхват.

**Это объясняющая модель, а не предсказание исхода.** Геометрия хвата, доли
силы пальцев и ширина контакта — оценки, а не измерения. Тело, старт и
усталость в модели не учтены. Выводы выше стоит проверить на видео реальных
схваток, прежде чем давать их как совет.

## Проверка нагрузок

```bash
npm run check:armlab
```

Скрипт проверяет механику упражнений методом виртуальной работы. Для каждого
сустава он немного меняет угол на настоящей модели руки и смотрит, какую работу
при этом совершает сила троса и вектор усилия спортсмена. Знаки сравниваются с
направлением движения, поэтому зеркало и выбор осей на результат не влияют.

Проверяются все варианты сопротивления каждого упражнения, каждый со своими весами мышц.

- **Движущийся сустав** (≥ 8°): сопротивление обязано мешать движению, а
  мятная стрелка — вести его. Если нет — ошибка, и скрипт завершается с ненулевым кодом.
- **Неподвижный сустав, который сопротивление сильно нагружает:** у мышц,
  которые его удерживают, должен быть заметный вес. Иначе выводится
  предупреждение. Наружные ротаторы теперь есть в модели, поэтому плечо
  проверяется в обе стороны.
- **Схватка:**
  - зеркальные схватки — ничья при любой глубине;
  - обмен сторонами (с обменом высоты) даёт обратный исход;
  - замок сходится: зазор меньше 0,5 мм, ладони напротив;
  - в «крюке против крюка» за вращение почти не борются, а в «крюке против
    верха» борются;
  - более высокая кисть выигрывает;
  - на мелком хвате у сильных рук нижняя кисть теряет хват, а глубокий хват
    её спасает;
  - ремни снимают нагрузку с пальцев;
  - при срыве руки остаются в замке, а при срыве хвата кисть выходит из захвата.

Так нашлась ошибка в первой версии «Крюка». Трос тянул от груди спортсмена и
сам делал за него капинг, закрытие локтя и боковое давление. Сейчас трос идёт
со стороны соперника и мешает всем четырём движениям крюка.

## Что дальше

- **Бот и сервер.** grammY (TypeScript) или aiogram (Python) и Postgres.
  Проверять `initData` на сервере (HMAC от токена бота), прежде чем выдавать
  что-то платное: `initDataUnsafe` годится только для показа имени.
- **Оплата.** Цифровые товары в Mini Apps продаются за Telegram Stars.
  Подписку создаёт `createInvoiceLink` с `subscription_period`.
- **n8n** — для автоматизаций вокруг бота: напоминания, приветственные цепочки,
  очередь видео на разбор тренеру. Webhook бота держит сервер и пересылает
  события в n8n, потому что webhook у бота может быть только один.
- **Контент.** Заменить процедурную анатомию на модель от 3D-художника (glTF),
  а позы записать с настоящего спортсмена (video-to-mocap). Формат данных
  упражнений при этом не меняется.
